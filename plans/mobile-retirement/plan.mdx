# Outcome

The Android experiment's owning Alchemy graph was destroyed at deployment revision `707e3fa`. CloudFormation removed the host stack, its instance, 50 GiB root EBS volume, network resources and IAM role/profile. The same graph removed the Cloudflare Tunnel, DNS record, zone-scoped Access application and verification service token. Provider-side absence checks corroborate Alchemy's successful exit.

PRs #5 and #6 were closed without merging. Their Alchemy cleanup jobs succeeded, and the exact Workers, custom domains/DNS, D1 databases, R2 buckets and stage state were verified absent. Only then were the three orphaned mobile-development state namespaces deleted. Production, shared Alchemy infrastructure, the reused one-time-PIN provider and unrelated projects remain intact.

After the initial conservative retention decision, the owner explicitly authorized both older AWS backup sets for deletion. The unused 2025 AMI was deregistered before deleting its two exclusive EBS snapshots; the old RDS final snapshot was deleted through AWS and its deletion waiter succeeded. A further 108 product/region checks across all 18 enabled regions found no owned AMIs, EBS snapshots, manual RDS or cluster snapshots, retained RDS automated-backup records or AWS Backup vaults.

**Incomplete owner-authenticated step:** Expo's proof project still exists because its deletion requires password confirmation in sudo mode. The dedicated proof robot's only publishing token is revoked, and `EXPO_TOKEN` / `EAS_PROJECT_ID` are absent from GitHub. The original `mobile-preview` checkout and reconstructed teardown checkout remain available for that secure owner step. Do not describe all retirement acceptance criteria as complete.

# Visible behavior

No application UI changed and no mobile source was merged into `main`. After teardown, the real production home and `/login` rendered correctly in Chromium with no console errors. The email textbox and Send a code button were observed without submitting the form or sending email.

The two known proof app identities were uninstalled from local simulators. Each simulator was returned to its prior shutdown state, and supported app-container lookups reported not found. The physical iPhone was unavailable, so its installed preview app was not touched. Shared SDKs, simulator devices and signing certificates were preserved. Two older simulator variants without confirmed current-project linkage were not guessed into the deletion allowlist.

# Contract and data boundaries

Application contracts, schemas, migrations, dependency versions, lockfile and production workflows are unchanged. This work removed owned operational resources and publishing capability, not web features or production data.

- Removed: `ProofAndroidPreviewProbe/probe`, `Proof/pr-5`, `Proof/pr-6`, `Proof/dev-expo-mobile`, `Proof/dev-mobile-preview` and `Proof/dev-mobile`.
- Preserved: `Proof/prod`, `Proof/dev_fawwaz.alharbi`, `Proof/temp`, the shared state worker/Secrets Store, production CI/R2 signing tokens and the operator AWS credential.
- The already absent temporary APK-artifacts stack and bucket were not recreated merely to delete them.

Alchemy's ownership boundary is the selected stack and stage, not the entire provider account. The probe and each PR preview needed their own graph destruction. The old AMI/EBS and RDS backups were outside Alchemy ownership and required explicit AWS deletion. Shared resources and externally created Expo projects are not automatically disposed merely because the template stack is brought down.

## Costs are not a universal zero

The probe's stopped-host storage was a 50 GiB gp3 disk, approximately $4.80 for a full month at the observed regional rate. Its absence removes that continuing resource; deleting Git refs alone would not have done so. Cost Explorer's estimated October 7 gp3 charge of $0.0490555555 includes pre-deletion usage and can still appear on the next invoice. A full post-deletion billing day has not yet settled.

The owner subsequently authorized and completed deletion of the old AMI/EBS and RDS backup sets. Their earlier storage usage can still appear on a delayed invoice, alongside one-time API-request usage from the inventory itself. The unrelated older S3 bucket was preserved after verifying zero current objects, object versions, delete markers and multipart uploads; the SST IAM connector and shared operator credentials were also preserved. Three invalid AWS profiles and unauthenticated Cloudflare, Apple and Google subscription coverage remain outside an account-wide zero-cost claim.

## Remaining prerequisites

1. The owner must run the interactive project deletion in the retained mobile-preview checkout and confirm the password locally, not in chat. The investigation checkout lacked the EAS binary; its wrapper swallowed that spawn error and returned code 1. The known-working pinned CLI is in the original mobile-preview checkout.
2. Confirm Expo project absence, then remove the retained original and reconstructed checkouts and the last local mobile-preview branch. The dedicated token is already revoked. Optional deletion of the now-inactive robot also requires sudo mode.
3. The physical phone's preview app can be removed when the phone is available; it no longer has an experiment backend or a valid proof publishing credential.
4. The prior backup-retention decision is resolved: both old backup sets are deleted. Any unrelated account membership cancellation still requires its own authorization and billing evidence.
